## 怎么回放的

- **输入**：每支案例 README 开头的场景描述（`news-artemis` 是「场景」一条，另外两支加上「商品」「规矩」或「这节课教什么」）。段落参考案例已定的 `case.json`。
- **按 Skill 走**：复制两份模板，阶段 1 写立意、段落、取舍、缺口，阶段 2 按缺口补，最后跑 `check.py --handoff`。
- **事实来源**：案例自带的 `script.json`、`case.json` 和里面的链接，2026-11-08 逐个重新下载、抽正文核对；案例没给来源的（护肤的法规、课件的短片题目），按 Skill 去找。读不到的照实写「没读成：原因」。
- **确认记录是模拟的**：回放里没有真的用户。用户的确认照案例 README、`case.json` 已定的写；案例没定、按 Skill 应该问用户的，按推荐项记，都标了「回放模拟」。

## 没改、建议维护者定的

- **核心内容引用了一个没有数据的单元**（例如只写「U2」，U2 一节的表是空的），`--handoff` 目前不报。`edge-unreadable` 的中间态里遇到了：那次被缺口 Q1 挡住了，没漏过去，但换个写法就可能漏。要加的话是 SPEC 第 9 节新的一行检查，所以没动。
- **确认记录可以写「回放模拟」这类括注**，脚本已经放宽；要不要在模板里写明，没动模板。

## 接手测试

2026-11-09 做。用 `create_session` 开了一个新的云端会话（`session_01Hy1rvaxZTyqWca5wWXksTT`），提示只给两份文件的路径，要求不读仓库里别的文件、不上网，按 `plan.md` 给 P1–P9 每段写 3–5 句内容提要，再列出「没法从这两份文件里得到、还要另查的」和「看着不对的」。

- **结果**：9 段提要全部写出，事实都带了编号，没有编出 `research.md` 以外的事实。另查的只列了 3 类：素材链接（本来就是 Q6、Q7 归分镜后）、画面读数（Q5）、复核 4,111 英里。按 SPEC 第 4 节「下一个人不用再调研核心内容」，判通过。
- **它查出的、已改的**：
  - 252,756 − 248,655 = 4,101 英里，NASA 博客写 4,111 英里，P6、P9 和 `example/` 都用了 4,111 → U5-2 标「有冲突」不引用，加 U9-4（相减），缺口 Q10 改内容关闭；`example/` 同样处理（U3-2、U4-3、Q4）。
  - 取舍写 8,283 公里、U4-5 是 8282 → 取舍改写清两者的来历。
  - 「41 分钟」没说是计划时段 → P5 改「按计划 …，约 41 分钟」。
  - 「半个多世纪来第一次」「三个第一位」是 NASA 2023 年的说法（`C1`、`A1`），段里没点明 → P3、P6 加「NASA 2023 年…说」。
  - 「登月任务」：原文是 lunar mission → U5-5、P6 改「月球任务」。
  - P1「绕到月球背面」只引了 U1-1 → 加 U4-3。
  - 「约 966 公里」比原文「将近 600 英里」精确过头 → P5 改「将近 600 英里，约 960 多公里」。
  - P4 奔月点火的时间没写时区 → 写明 UTC。
  - 70,377 公里没说是离地面还是离地心 → U3-1 加说明，旁白说「约 7 万公里」。
  - NASA 计划页的「10-23 更新」和「页面 11-04」看不懂 → 重读页面：讲的是 10-23 的通报，页面 11-04 发布，照这个写。
- **它提了、没改的**：Hansen 原话中文只译了一部分（翻译归分镜写旁白时定）。
