# 交接说明（格式 3）

给下游 Skill（做视频、PPT、课件、报告等）看：策划交出来的是什么、怎么读、能改哪里。下游的用户不一定装了策划，所以这里写全，不靠别的文件。

## 1 文件

用户项目里的 `plans/<短名>/`：

| 文件 | 是什么 |
|---|---|
| `plan.md` | 格式版本、状态和确认记录、需求、**效果**、**形式**、立意（主线和打法）、框架、效果自查、**说法**、衍生、取舍、缺口表 |
| `content.md` | 资料清单、**受众**、**素材**、**约束**、每段一节（信息和素材）、待核实和有冲突、检索记录 |
| `source/` | 原文（可能没有；私密的不进公开仓库） |

想先看一份精简版：`python3 -I <策划 Skill 目录>/scripts/brief.py plans/<短名>`，从两份文件生成，不存档。没装策划的，直接读两份文件。

## 2 先认格式和状态

- `plan.md` 第二行是 `格式：ai-content-planner/3`。版本号不认识，就停下，请用户更新下游或策划，不要猜着读。
- 状态行是「已交接」才接。「回流中」表示策划还在处理下游提的缺口，等它改回「已交接」。
- 确认记录里「效果」「框架」写着「自动，未问用户」的，用户没看过；下游开工前可以先请用户过一眼。

## 3 能用的编号

| 编号 | 是什么 | 写在哪 |
|---|---|---|
| `P1` | 段 | `plan.md` 框架的「段」；`content.md` 每段一节的标题 |
| `a`、`b` | 段里要讲的点 | 框架「要讲的点」（`a. ……<br>b. ……`）；说法的「点」写 `P1 a` |
| `P1-1` | 一条信息或素材 | `content.md` 每段一节的「#」 |
| `V1` | 一条受众原话或行为 | `content.md` 受众 |
| `M1` | 一张图、一段视频（或同类的一组） | `content.md` 素材 |
| `K1` | 一条画面约束 | `content.md` 约束 |
| `D1` | 一条衍生（拆条、别的版本） | `plan.md` 衍生 |
| `Q1` | 一条缺口 | 缺口表「编号」 |
| ①② | 效果的一条阻力 | `plan.md` 效果「阻力」 |

编号只增不改：删掉的号空着，不会被别的内容占用。框架按成品里的顺序排，编号可以不连续。

## 4 怎么读

- **效果**（接触时刻、起点、阻力、终点、衡量、杠杆）是这份内容要做成的事。**框架**每段写「受众：从 → 到」，就是这一段要把受众从哪个念头带到哪个念头；「怎么证明」是用什么让人信。
- **形式**：结构、声音、证明方式、注意力预算是从效果推出来的效果要求；视觉风格、配乐、剪辑节奏归下游。
- **要讲的点**是这段要讲的具体内容，下游照它写，不另起炉灶。
- **说法**：每个点要的效果、一句参考说法、不能丢的底线和依据。
- `content.md` 每条有讲哪一点、内容、种类、来源、必须写清的、状态。「（P3 b 也用）」表示 P3 的 b 也用这一条；「不用」是记着备查、成品里不讲的，下游也不要用。交接时被用到的信息都是「已核实」或「设定」。种类 `C4`（某方自己说的）讲成「官方称」「按计划」「我们」，不讲成第三方的事实。
- **素材**一张一行：图上的字、标志、水印、人脸，能怎么用（原样、裁后用、重画、只作参考），能不能送进生成模型。
- **约束**是任何生成、重画、合成的画面都要守的样子：产品结构、人物外观、场所、界面、抽象意象的具体参照。

## 5 下游的规矩

1. **说法**：字可以改，节奏可以改；「要的效果」不能改；「不能丢的」一条不能少；不能加新的宣称。
2. **约束**：生成、重画、合成的画面逐条对照 K，违反算返工；素材「能不能送生成」写「不能」的不进生成模型，写〔待核实〕的按「不能」处理；「只作参考」的不进成品。
3. **形式**：结构、声音、证明方式要改，先在缺口表加行回流，不自己改。
4. 产物放在下游自己的目录（视频是 `videos/<短名>/`），不写进 `plans/`；产物里写明来自哪份 `plan.md`；引用段号写 `seg`（`"P1"`），引用事实写 `ref`（`"P1-1"`，设定写 `null`），引用约束写 `rule`（`"K1"`）。一段策划可以拆成下游的几段。

## 6 下游能改哪里

只许改 `plan.md` 的两处，别的不改，也不改 `content.md`：

1. **缺口表加行**：`编号` 接着最大的 Q 往后编；`段` 写段号或「全部」；`提出于` 写「下游」；`状态` 写「待补」。缺内容（缺步骤、缺解释、结论站不住、形式要改）→ `归谁` 写「策划」；只缺素材 → `归谁` 写「下游」，下游自己处理，处理完改成「已补」、写「怎么解决的」。
2. **状态行**：加了归「策划」的行，就把状态改成「回流中」，请用户转给策划。

策划处理完会改回「已交接」；下游按当时的框架接着做，不恢复已删的内容。

## 7 格式升级

改节名、表头、取值、编号规则时，格式号加 1，策划的 CHANGELOG 写明怎么从旧格式转（格式 1 → 2 见 CHANGELOG 0.4.0）。从格式 2 转格式 3（策划 0.6.0）：

| 格式 2 | 格式 3 |
|---|---|
| 需求八项 | 需求五项：用途和场景、必须有、不要、已有材料、品牌与风格；「给谁看」并进效果「起点」；「输出形式」「篇幅与规格」挪进形式「输出形式和规格」「篇幅和注意力」 |
| 立意三项 | 「看完得到什么」改写成效果「终点」；「一句话主线」改成立意节里的一行「一句话主线：」；「怎么讲」拆进形式的结构、声音；加打法表 |
| — | 新节：效果（六项）、形式（七项）、效果自查（五项）、说法、衍生；`content.md` 新节受众、素材、约束 |
| 框架六列 | 七列：「受众收益」改「受众：从 → 到」，加「怎么证明」 |
| 状态「需求待确认」、确认记录「需求」 | 「效果待确认」、「效果」 |
