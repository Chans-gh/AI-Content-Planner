# 交接说明（格式 2）

给下游 Skill（做视频、PPT、课件、报告等）看：策划交出来的是什么、怎么读、能改哪里。下游的用户不一定装了策划，所以这里写全，不靠别的文件。

## 1 文件

用户项目里的 `plans/<短名>/`：

| 文件 | 是什么 |
|---|---|
| `plan.md` | 格式版本、状态和确认记录、需求、立意、框架（内容流程和段落表）、取舍、缺口表 |
| `content.md` | 内容表：资料清单、每段一节（信息和素材）、待核实和有冲突、检索记录 |
| `source/` | 原文（可能没有；私密的不进公开仓库） |

## 2 先认格式和状态

- `plan.md` 第二行是 `格式：ai-content-planner/2`。下游先认这一行：版本号不认识，就停下，请用户更新下游或策划，不要猜着读。
- 状态行是「已交接」才接。「回流中」表示策划还在处理下游提的缺口，等它改回「已交接」。
- 确认记录里「需求」「框架」写着「自动，未问用户」的，用户没看过需求和框架；下游开工前可以先请用户过一眼。

## 3 能用的编号

| 编号 | 是什么 | 写在哪 |
|---|---|---|
| `P1` | 段 | `plan.md` 框架的「段」；也出现在「作用」（承接哪段）、缺口表「段」；`content.md` 每段一节的标题 |
| `a`、`b` | 段里要讲的点 | 框架「要讲的点」（`a. ……<br>b. ……`）；`content.md`「讲哪一点」 |
| `P1-1` | 一条信息或素材（`content.md` 里 `## P1` 一节的表） | `content.md` 的「#」；缺口表「怎么解决的」 |
| `Q1` | 一条缺口 | 缺口表「编号」 |

编号只增不改：删掉的号空着，不会被别的内容占用。框架按成品里的顺序排，编号可以不连续。

框架的段落表六列：`段 | 作用 | 受众收益 | 要讲的点 | 用到哪些输入 | 篇幅`。「要讲的点」是这段要讲的具体内容，下游照它写，不另起炉灶；「篇幅」的单位跟需求的「输出形式」走（视频写秒，PPT 写页，报告写字，或「不限」）。

`content.md` 每条有：讲哪一点、内容、种类（代号如 `B1`；虚构的写「设定」）、来源、必须写清的、状态。「讲哪一点」写本段的字母；「（P3 b 也用）」表示 P3 的 b 也用这一条，P3 那节不重复记；「不用」是记着备查、成品里不讲的，下游也不要用。交接时被要讲的点用到的信息都是「已核实」或「设定」。种类 `C4`（某方自己说的）要讲成「官方称」「按计划」，不讲成事实。种类 `F1`–`F3` 是承担信息的素材（图表、截图、录像片段），「来源」写链接或 `source/` 下的路径，「必须写清的」写授权；装饰性的素材不在这里，在缺口表归「下游」。

## 4 下游的产物放哪、怎么引用

- 放在下游自己的目录（视频是 `videos/<短名>/`），不写进 `plans/`。
- 产物里写明来自哪份 `plan.md`（例如 `"plan": "plans/<短名>/plan.md"`）。
- 引用段号写 `seg`（`"P1"`）；引用事实写 `ref`（`"P1-1"`；设定写 `null`）。一段策划可以拆成下游的几段。

## 5 下游能改哪里

只许改 `plan.md` 的两处，别的不改，也不改 `content.md`：

1. **缺口表加行**：`编号` 接着最大的 Q 往后编；`段` 写段号或「全部」；`提出于` 写「下游」；`状态` 写「待补」。
   - 缺内容（缺步骤、缺解释、结论站不住）→ `归谁` 写「策划」，回到策划处理；
   - 只缺素材（缺一张图、一段录屏）→ `归谁` 写「下游」，下游自己处理，处理完把状态改成「已补」、写「怎么解决的」。
2. **状态行**：加了归「策划」的行，就把状态改成「回流中」，请用户转给策划。

策划处理完会改回「已交接」；下游按当时的框架接着做，不恢复已删的内容。

## 6 格式升级

改节名、表头、取值、编号规则时，格式号加 1，策划的 CHANGELOG 写明怎么从旧格式转。只加说明、不改结构的，格式号不变。

从格式 1 转格式 2（2026-11，策划 0.4.0）：

| 格式 1 | 格式 2 |
|---|---|
| `research.md` | 改名 `content.md` |
| 立意十项 | 「需求」八项：用途→用途和场景，给谁看、输出形式、篇幅与规格照搬，不讲什么→不要，已有品牌与风格→品牌与风格，新加必须有、已有材料；「立意」三项：看完得到什么、一句话主线、怎么讲；凭什么信去掉 |
| 「段落」：核心内容、素材编排 | 「框架」：先写「内容流程：」一句；核心内容按「；」拆成要讲的点 `a. ……<br>b. ……`，编号从点里拿掉；素材编排去掉（要的素材在缺口表）；加「用到哪些输入」 |
| `## U1 单元`，编号 `U1-1` | `## P1 段的作用` 每段一节，编号 `P1-1`：每条记在第一次用到它的段和点，别的段写「（P3 b 也用）」，没被引用的写「不用」；正文和缺口表里的 U 编号换成新编号 |
| 「要哪些单元」一节 | 去掉 |
| 检索记录四列 | 加「谁查的」 |
| 确认记录「方向」 | 拆成「需求」「框架」两行 |
| 状态：阶段 1 整理中 / 阶段 1 待确认 / 阶段 2 补齐中 | 需求待确认 / 框架待确认 / 补齐中 |
| 缺口「提出于」：阶段 1 / 阶段 2 | 第 1 步 / 第 2 步 / 第 3 步（阶段 2 → 第 3 步） |
| 下游引用 `ref: "U1-1"` | `ref: "P1-1"` |
