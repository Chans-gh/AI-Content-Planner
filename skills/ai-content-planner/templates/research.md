# 资料底稿：〔片名〕

> 成品里讲的每条事实、数字、说法、步骤，都要在这里找得到出处；`plan.md` 的段落和缺口引用这里的编号。种类代号见本 Skill 的 `types.md`。
> 一个**信息单元**（U1、U2……）回答一个问题或撑一条结论；单元里每条**信息数据**（U1-1、U1-2……）一句话一件事，标一个种类。
> 状态：**已核实** / **〔待核实〕** / **有冲突** / **已过期**；创作设定写 **设定**。交接前，核心内容用到的数据不能是〔待核实〕或有冲突。编号只增不改：删掉的号空着，补的接着往后编。
> 「内容」写信息本身：数字带单位、口径、时间；步骤带前提、顺序、成功标志。不能只写「见某报告第 3 页」。

## 资料清单

用户给的和自己找到的都记。`读到哪` 照实写，没读成的写原因；`用途` 取「内容依据 / 素材 / 参考」，可多选，用「、」隔开。私密的、很大的文件只记一笔，不复制进公开产物。

| 资料 | 位置 | 读到哪 | 用途 | 能不能公开 | 用到哪些编号 |
|---|---|---|---|---|---|
| 〔名称〕 | 〔链接或文件路径〕 | 〔全文 / 第 x–y 页 / 第 n 节 / 00:12–01:40 / 没读成：原因〕 | 〔内容依据、素材、参考〕 | 〔能 / 不能 / 只用摘要〕 | |
